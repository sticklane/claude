# Grounding must be a separate validation pass

## Incident

A factual claim in the design-doc session was accepted from prior context but was
not validated in the same pass as writing. A separate grounding run later caught a
fabricated claim.

## Lesson

Do not treat grounding as implicit to normal drafting or critique.
After each drafting or design sweep that introduces factual claims, run a dedicated
grounding pass before treating the session as complete.

## Trigger

Use this lesson for any session that introduces durable factual statements into repo
guidance or architecture documentation.
